Password reset in a banking app

User: a retail customer locked out of mobile banking · Goal: get back in safely · Success: signed in with a new password, and the change confirmed

Entry points: "Forgot password" on the login screen · too many failed sign-ins · a forced reset after a security alert

What changed

  • Email link → one-time code in the app. The code arrives where the user already is and fills itself, so there is no inbox hunt and no link to expire unseen.
  • Long verification form → biometric check. Face ID proves identity in one step. People without it on this device get a PIN or ID scan instead.
  • Silent reset → signed in with an alert. The user lands in the app, and a "Wasn't me?" alert covers account takeover.

Edge cases and open questions

  • Shared family phones: should biometrics count when another person's face is enrolled?
  • Lost phone: the reset must work from a new device without the old one, through ID scan or support.
  • Rate limits: five wrong codes pauses for 30 minutes. Is that too strict for older users?
